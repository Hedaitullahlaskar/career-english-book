## Why the 14 units are not generated yet

**D-U10 (approved) makes ChatGPT the curriculum-generation engine.** It says Claude Code must not replace it unless the author changes that decision. This environment has no ChatGPT/OpenAI access (no API key is configured), and Claude Code may not write the content itself.

So this build delivers everything assigned to the repository layer:
- registry, schemas and the U-1 Role Profiles and Role Instances;
- retrieval-before-generation plans;
- **ready-to-send ChatGPT request packets**;
- ingest, with validation, de-duplication, ID and vocabulary-code assignment, and AI QA;
- composition and search tests;
- an end-to-end pipeline test on synthetic data.

The units are generated by sending the request packets to ChatGPT (`editorial/curriculum/requests/PROMPT-ENVELOPE-v1.md`) and ingesting the replies.

## 7. AI QA findings

**No real content exists yet,** so there are no AI QA findings on curriculum content. AI QA runs automatically on every ingested object.

**What AI QA checks:**
- schema;
- CEFR match;
- function coverage in learner turns;
- excluded functions not used;
- turn counts;
- learner-turn length per CEFR level;
- new-vocabulary counts;
- task counts;
- **no Bengali/Devanagari script**;
- US spellings;
- real brand names;
- driving/safety wording in DRV-constrained units;
- answer-key coverage;
- rubric totals (100);
- **anti-noun-swap** (P5 against P4: word overlap above 0.60 fails);
- the A2 variant shorter than its B1 base;
- an L4 "difference statement" present.

**Verified in the pipeline test:**
- identical P4/P5 conversations **were caught** (industryRealism error);
- an invented vocabulary code **was caught**.

Each object gets four separate review records:
- **AI_QA** = PASS/FAIL (pipeline);
- **EDITORIAL_REVIEW** = PENDING (author);
- **SPECIALIST_REVIEW** = NOT_REQUIRED (with reason);
- **NATIVE_REVIEW** = NOT_REQUIRED (with reason).

## 10. Unresolved issues

1. **Generation not done (by design).** ChatGPT must generate L0–L6 through REQ-000001…000011. If the author wants it automated, an OpenAI API key and explicit permission would be needed; otherwise the packets are sent manually.
2. **Test-drive unit (RIN-000005, STM-0026):** the situation template carries a DRV (driving-safety) trigger. To keep U-1 specialist-free, CFN-0108 (safety instruction) is **excluded**, and the unit is limited to arranging the test drive, with no driving or traffic instructions. **The author should confirm that this keeps Specialist Review NOT_REQUIRED.**
3. **Food Delivery Executive** carries a DRV trigger in the role registry. The three units are about communication, with no traffic advice, and AI QA flags driving wording. **The author should confirm.**
4. **D-U07 example "V-RETAIL-0001":** `RETAIL` is not a registered scope. The registry's retail scopes are the sector `TRADE`, the role family `RTLF` and industries such as `SMKT` or `APRL`. As implemented, unregistered scopes are rejected. Registering a 6-letter `RETAIL` alias would need a registry decision.
5. **Vocabulary scope rule:** the family scope is used when the role appears in more than one industry, otherwise the industry scope. This is a reasonable default, but it is **not yet an explicit author decision**.
6. **Search ranking quality:**
   - "hotel check-in" ranks Hotel Sales Executive and Airline Check-in Agent above Front Office Executive (all within the top 3);
   - "BLO field visit" ranks BLO Supervisor above Booth Level Officer.
   - A production search needs relevance tuning and real query logs.
7. **Token estimates** are character-based approximations, and prices are unset.
8. **The validator implements a JSON Schema subset** (`jsonschema` is not installed). Installing it would allow full-spec validation.
9. **No ChatGPT reply format has been tested yet.** Ingest tolerates Markdown fences, but the first real replies may reveal format issues to fix in the prompt envelope.
